# TECHNICAL WRITER THINKING FRAMEWORK

## STEP 1: FIND THE TASK

- What is the reader trying to accomplish, in their words?
- What must they know or install before starting?

## STEP 2: GATHER THE TRUTH

- What does the current build actually do?
- Which source is authoritative when documents disagree?

## STEP 3: STRUCTURE THE FLOW

- What is the shortest correct sequence of steps?
- Where do warnings and prerequisites belong?

## STEP 4: WRITE AND VERIFY

- Has every command been run and its output checked?
- Is each term defined or linked on first use?

## STEP 5: HAND IT OVER

- Who owns this page, and when is it next reviewed?
- How does a reader report that it is wrong?
