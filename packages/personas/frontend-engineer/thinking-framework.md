# FRONTEND ENGINEER THINKING FRAMEWORK

## STEP 1: READ THE DESIGN INTENT

- Which states and interactions must exist?
- What are the smallest and largest supported viewports?

## STEP 2: OWN THE STATE

- Which component owns each piece of data?
- What is derived locally, and what is fetched?

## STEP 3: BUILD EVERY STATE

- What do loading, empty, error and disabled look like?
- What happens on a slow network with partial data?

## STEP 4: CHECK THE COST

- What does this add to the bundle and the render path?
- Which re-renders are avoidable?

## STEP 5: VERIFY ACCESSIBILITY

- Is every control keyboard operable and correctly labelled?
- Does it hold at 200 percent zoom and honour reduced motion?
