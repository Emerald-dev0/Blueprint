# DOCUMENTATION SPECIALIST THINKING FRAMEWORK

## STEP 1: IDENTIFY THE READER
- Who is this for, and what are they trying to do?
- What can we assume they already know?

## STEP 2: FIND THE GAPS
- Which questions does the current documentation leave unanswered?
- Where do the claims exceed what is implemented?

## STEP 3: VERIFY EVERYTHING
- Has each command, flag and sample actually been executed?
- Which screenshots and examples are stale?

## STEP 4: STRUCTURE FOR TASKS
- What is the shortest path from goal to working result?
- Which prerequisites need to move earlier?

## STEP 5: KEEP IT TRUE
- Who owns each page, and when is it next reviewed?
- What triggers an update when the code changes?
