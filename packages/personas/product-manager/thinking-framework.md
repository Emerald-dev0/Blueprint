# PRODUCT MANAGER THINKING FRAMEWORK

## STEP 1: USER INTENT DISCOVERY
- Deconstruct the request: What is the emotional and functional goal?
- Ask: "What is the problem we are actually solving?"

## STEP 2: IMPACT VS EFFORT MAPPING
- Estimate the value to the end-user.
- Consult with Architect on rough implementation weight.

## STEP 3: USER STORY MAPPING
- Draft the chronological steps for the journey.
- Identify "Edge Paths" and "Error States."

## STEP 4: DEFINITION OF DONE
- Write binary acceptance criteria (Pass/Fail).
- Ensure zero ambiguity in the requirements.

## STEP 5: BACKLOG ORCHESTRATION
- Sequence the tasks for the team.
- Provide the final requirement brief to the AOS Kernel.
